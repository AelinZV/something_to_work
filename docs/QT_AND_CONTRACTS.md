# Qt 6 и добавление новых контрактов

## Как устроена графика

`src/gui/main.cpp` — графический слой Qt 6: `GameWindow` создаёт панели и связывает кнопки с `GameService`.

- `CoverBanner::paintEvent()` — обложка с сохранением пропорций и обрезкой по центру.
- `WorldMap::paintEvent()` — рисование карты в относительных координатах; `mousePressEvent()` — выбор пункта путешествия.
- `GameWindow::resizeEvent()` и `src/gui/ResponsiveLayout.h` — политика адаптивной компоновки: шире 1120px — три колонки, уже — вкладки. В `QSplitter` пользователь может вручную менять ширину колонок.
- `QTextBrowser` — текст заказа с переносом и прокруткой. `QPlainTextEdit` — журнал с прокруткой.
- `QScrollArea` — список/карта и управление на маленьком дисплее.

Если хочется изменить стиль/цвета, в начале `src/gui/main.cpp` есть `kStyle` (Qt Style Sheets). Для замены фонового изображения — `assets/cover.png`.

## Где хранится контракт

В обычном режиме PostgreSQL контракт — строка таблицы `contracts`. Связанное чудовище — строка `monsters`. У каждого контракта уникальное `id`, но `location_id` может повторяться у сколько угодно контрактов.

Новые контракты не требуют изменений C++ кода, если местоположение уже существует (значения `1` — Топь, `2` — Мельница, `3` — Чёрный бор) и слабость чудовища известна игре (`fire`, `silver`, `sigil`).

- Создать монстра в `monsters` и контракт в `contracts`.
- Связать его с существующей локацией через `location_id`.
- Перезапустить игру: каталог читается `PgGameRepository::listContracts()` при создании `GameService`.
- Выбрать героя. `PgGameRepository::loadProgress()` добавляет недостающие пары `(hero_id, contract_id)` без удаления прежнего прогресса.
- `GameWindow::refresh()` создаёт группу для `location_id` и отдельный элемент списка с `Qt::UserRole=contracts.id`. `selectedContract()` получает ID, все действия получают именно его.

## Пример (повторно безопасен)

```bash
pg_dump "$BORDERLAND_DB" -f borderland_backup.sql
psql "$BORDERLAND_DB" -v ON_ERROR_STOP=1 -f sql/add_contract_example.sql
psql "$BORDERLAND_DB" -c "SELECT id,title,location_id FROM contracts ORDER BY location_id,id;"
```

После перезапуска в локации **Топь** будет два заказа, например исходный «То, что дышит в болоте» и новый «Огни над трясиной» (ID 4). При этом в игре пока ограничение: одновременно вести бой можно только с одним чудовищем, но заказы можно принять и расследовать отдельно.

**Важно:** `--demo` использует отдельный набор тестовых контрактов в `src/repository/MemoryGameRepository.cpp`, не читая PostgreSQL. Чтобы увидеть новый SQL-контракт, запускайте без `--demo`.

## Ограничения и безопасность

- Не меняйте `contracts.id` у существующих записей. Связанные сохранения опираются на этот ID.
- Не удаляйте контракт, если на него уже ссылаются `hero_contracts`.
- Для новых локаций потребуются изменения карты и ограничений в модели и SQL, но добавление контрактов в существующие локации требует только SQL.
- SQL скрипты запускайте на резервной копии либо после `pg_dump`; не используйте `DROP TABLE` и не пересоздавайте рабочую базу.
